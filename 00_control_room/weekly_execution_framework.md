# Weekly Execution Framework

## Study Capacity

- Sunday–Thursday: 5 hours/day
- Friday: 10 hours
- Saturday: 10 hours
- Total: 45 hours/week
- One session: 5 hours
- Total sessions: 9 per week

---

# Default Weekly Allocation

A normal week should approximately contain:

## 4 Sessions — Core Technical Development

Examples:

- Python
- PyTest
- CAN
- UDS
- CANoe
- Debugging
- CI/CD

## 3 Sessions — Hands-On Automotive Work

Examples:

- Automotive coding tasks
- Test automation
- CAN/UDS scenarios
- Log investigation
- Portfolio project development

## 1 Session — Quality / ISTQB / Test Lead Thinking

Examples:

- Test design techniques
- Risk-Based Testing
- Defect Management
- Software Quality
- ASPICE
- Test planning
- Release-risk scenarios

## 1 Session — Weekly Assessment and Portfolio Review

Includes:

- Integrated practical task
- Interview question
- Weakness review
- Git review
- Progress tracker update
- Next-week priorities

This distribution can change when a phase requires more or less hands-on time.

---

# Standard 5-Hour Session Structure

The exact timing is flexible, but a typical session may contain:

## Part 1 — Review and Warm-Up

- Brief recall of the previous session
- One small integrated exercise if needed

## Part 2 — New Concept

- Small explanation
- Automotive example
- Edge cases / boundary values

## Part 3 — Independent Automotive Task

Rizk performs:

- Analysis
- Pseudocode
- Implementation
- Manual tests
- Edge cases

## Part 4 — Review and Repair

Classify issues:

- Problem Decomposition
- Logic
- Syntax
- Edge Cases
- Testing
- Code Quality

## Part 5 — Evidence

Where appropriate:

- Run tests
- Update Markdown notes
- Git commit
- Push
- Update progress tracker

---

# Weekly Definition of Done

A week is not complete because topics were explained.

There must be meaningful evidence.

## Technical

- Important concepts understood

## Hands-On

- Automotive implementation completed

## Testing

- Manual or automated tests executed

## Edge Cases

- Relevant boundaries and negative cases considered

## Quality

- Relevant ISTQB / Software Quality concepts applied

## Automotive

- At least one realistic Automotive scenario completed

## Git

- Meaningful commits created

## Interview

- At least one technical or behavioral answer practiced

## Leadership

- Relevant Test Lead scenario practiced when appropriate

## Review

- Weaknesses identified

## Next Step

- Next priorities updated

# Weekly Review Questions

At the end of each week answer:

1. What can Rizk now do independently that he could not do at the start of the week?
2. Which concepts are still ORANGE?
3. Which concepts are INITIAL GREEN?
4. Which older concepts were demonstrated as MASTERED inside integrated work?
5. What code or documentation was added to GitHub?
6. What Automotive scenario was completed?
7. What testing/quality principle was applied?
8. What interview weakness appeared?
9. What leadership weakness appeared?
10. What is the highest-priority next step?

---

# Interview Practice Rule

Interview preparation runs continuously.

Preferred flow:

1. Ask one question.
2. Rizk answers first.
3. Evaluate:
   - Technical accuracy
   - Structure
   - English
   - Confidence
   - Relevance
   - Leadership maturity
4. Correct technical mistakes.
5. Correct important English issues.
6. Provide a stronger natural answer.
7. Ask one follow-up question.

# Git Rule

Meaningful work should normally end with:

```text
run / test
↓
git status
↓
git diff
↓
git add
↓
git commit
↓
git push
```

The repository is part of the professional portfolio, not only a storage folder.
