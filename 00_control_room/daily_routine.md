# Daily Study Routine

## Weekly Study Capacity

Total: 27 hours/week

- Friday: 8 hours
- Saturday: 4 hours
- Sunday-Thursday: 3 hours/day

---

# Friday Routine

Two sessions - 4 hours each.

## Session 1
Timing: After Friday prayer

### Structure

- 15 min - Review previous knowledge
- 60 min - New concept explanation
- 10 min - Break
- 70 min - Guided coding
- 10 min - Break
- 55 min - Independent exercises
- 20 min - Automotive application

Total: 4 hours

## Session 2
Timing: Evening

### Structure

- 20 min - Recall Session 1 without notes
- 50 min - Continue new concepts
- 10 min - Break
- 70 min - Hands-on coding
- 10 min - Break
- 40 min - Automotive exercise
- 20 min - Interview questions
- 20 min - Notes + Git commit

Total: 4 hours

---

# Saturday Routine

Timing: 1:00 PM - 5:00 PM

### Structure

- 20 min - Recall and review
- 50 min - Concepts
- 10 min - Break
- 70 min - Coding exercises
- 10 min - Break
- 40 min - Automotive practice
- 20 min - Interview practice
- 20 min - Notes + GitHub update

Total: 4 hours

---

# Sunday-Thursday Routine

Timing: 10:00 PM - 1:00 AM

### Structure

- 15 min - Recall previous session
- 40 min - Learn / explain new concept
- 10 min - Break
- 50 min - Hands-on coding
- 10 min - Break
- 30 min - Automotive exercise
- 15 min - Interview question + English explanation
- 10 min - Notes + Git status / commit

Total: 3 hours

---

# Core Learning Method

Every topic follows:

Learn -> Code -> Explain -> Automotive Application -> Interview Answer

---

# Coding Rules

1. Try the problem before asking for the solution.
2. Do not copy code without understanding it.
3. After solving, explain the code line by line when needed.
4. Prefer readable code over clever code.
5. Debug errors before replacing the solution.
6. Connect exercises to automotive testing whenever practical.

---

# Interview Routine

Every study day must include at least one technical interview question.

Answer structure:

1. Direct answer
2. Short technical explanation
3. Practical example
4. Automotive example when relevant

English answers should be simple, clear, and technically accurate.

---

# End-of-Day Check

Before finishing each session:

- What did I learn?
- What did I code myself?
- What did I struggle with?
- Can I explain today's topic?
- Can I apply it to testing?
- Did I save useful work to Git?

---

# Weekly Rule

Thursday is the final assessment day.

A weak topic is carried forward.

A topic is never marked complete just because it was studied.
