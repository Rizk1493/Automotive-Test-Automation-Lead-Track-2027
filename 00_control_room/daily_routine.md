# Daily Study Routine

## Purpose

Define the normal execution rhythm for the Automotive Test Automation Lead Track 2027.

The routine must support job readiness through a balance of technical learning, hands-on work, Automotive application, testing/quality thinking, interview preparation, and GitHub evidence.

---

# Weekly Study Capacity

- Sunday-Thursday: 5 hours/day
- Friday: 10 hours
- Saturday: 10 hours
- Total: **45 hours/week**
- One session: **5 hours**
- Total: **9 sessions/week**

The exact clock time is flexible unless a specific session time is agreed separately.

---

# Standard 5-Hour Session

A normal session is approximately 300 minutes.

## Part 1 - Recall and Context
**20 minutes**

- Recall the previous session without excessive rereading
- Identify where the roadmap stopped
- Reuse one older skill when useful
- Confirm today's expected evidence

## Part 2 - New Concept + Complete Automotive Example
**45 minutes**

- Explain one small concept
- Show why it matters
- Use an Automotive/Test scenario
- Walk through a complete example
- Highlight common mistakes

## Break
**15 minutes**

## Part 3 - Independent Automotive Task
**90 minutes**

For suitable coding tasks, Rizk performs:

- Requirement analysis
- Input / Output / Variables / Conditions / Repetition / Stop condition
- Pseudocode
- Implementation from a blank screen
- Manual test cases
- Edge cases / boundary values

Do not provide hints automatically.

## Break
**15 minutes**

## Part 4 - Review, Debugging, and Testing
**60 minutes**

Review mistakes as:

- Problem Decomposition
- Logic
- Syntax
- Edge Cases
- Testing
- Code Quality

Where appropriate:

- Execute the program/tests
- Investigate failures
- Improve test data
- Refactor only after correctness is established

## Part 5 - Professional Evidence
**30 minutes**

Depending on the phase, use this time for one or more of:

- ISTQB / Software Quality connection
- Interview question
- Test Lead scenario
- Markdown notes
- Test documentation
- Requirement traceability
- Defect/reporting practice

## Part 6 - Git and Progress
**25 minutes**

Where meaningful:

```text
run / test
↓
git status
↓
git diff
↓
git add
↓
git commit
↓
git push
```

Then record:

- What was completed
- Evidence created
- Current mastery state
- Main weakness
- Exact next step

---

# Friday and Saturday

Friday and Saturday contain **two 5-hour sessions each**.

The two sessions should not normally be five hours of continuous theory.

A useful pattern is:

## Session A
Core technical development + independent Automotive task

## Session B
Integration / deeper hands-on work / debugging / portfolio / assessment

The exact balance changes with the active roadmap phase.

---

# Sunday-Thursday

Normally one 5-hour session per day.

Each day should continue the active roadmap rather than restarting or selecting unrelated topics.

---

# Core Learning Cycle

For meaningful programming and automation topics:

```text
Explain
↓
Complete Automotive Example
↓
Edge Cases / Boundary Values
↓
Full Independent Automotive Task
↓
Review
↓
Integration
↓
Mastery Check
```

New topics should reuse old skills whenever practical.

---

# Coding Rules

1. Try the problem before asking for the solution.
2. Start from the Requirement, not from Python syntax.
3. Use Analysis and Pseudocode for suitable independent tasks.
4. Do not copy code without understanding it.
5. Prefer readable code over clever code.
6. Debug the current solution before replacing it.
7. Treat syntax mistakes separately from logic/decomposition mistakes.
8. Always consider relevant edge cases.
9. Prefer Automotive/Test scenarios whenever practical.
10. Commit meaningful evidence to GitHub.

---

# Practical ISTQB Rule

ISTQB Foundation concepts are integrated where they naturally improve engineering work.

Examples:

- Test basis / test conditions / test cases
- Equivalence Partitioning
- Boundary Value Analysis
- Decision Tables
- State Transition Testing
- Regression / confirmation testing
- Risk-Based Testing
- Defect Management
- Planning / estimation / monitoring / control

The purpose is job readiness and strong testing thinking, not exam memorization.

---

# Interview Rule

Interview training runs throughout the roadmap, but not every session must become a long mock interview.

Preferred flow:

1. Ask one question.
2. Rizk answers first.
3. Review technical accuracy, structure, English, confidence, relevance, and leadership level.
4. Improve only the important weaknesses.
5. Ask one follow-up when appropriate.

---

# End-of-Session Check

Before finishing:

- What can I now do independently?
- What did I build or test?
- Which older skill did I reuse?
- What edge cases did I consider?
- What mistake category appeared?
- What evidence was saved?
- Did I commit meaningful work where appropriate?
- What is the exact next step?

---

# Weekly Rule

The final session of each study week is the **Weekly Assessment and Portfolio Review**.

A weak skill remains ORANGE.

A skill becomes INITIAL GREEN only after direct independent evidence.

A skill becomes MASTERED only after later successful use inside integrated work without prompting.

A week is not complete merely because its topics were explained.
